# Profit tag on every recipe row of the profession window

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans.

**Goal:** In the game's profession window, show at the right of each recipe row of the list the money gained or lost by crafting it (e.g. `+12s 23c` green, `-2s` red), like the other addon "CraftProfit" 0.4.0 by Vystery does (reference only; its zip was unpacked for analysis in `/private/tmp/claude-501/-Users-juliani-Desktop-Dev-perso-wow-addons/63fa1d6b-1def-4885-b9f8-2ae5b512b9ca/scratchpad/cp04/CraftProfit/ProfessionUI.lua`, functions `EnsureRowWidgets`, `UpdateRow`, and the code around the `OnInitializedFrame` callback near its end; **do not copy its code, write ours**). Its technique: a font string created on each recycled list row; refreshed when the ScrollBox initialises a row (`ScrollBox:RegisterCallback(ScrollBoxListMixin.Event.OnInitializedFrame, ...)`) and by `ScrollBox:ForEachFrame` after data changes; each row's `elementData` gives `data.recipeInfo.recipeID` (its helper `NodeData(node)`). Its changelog notes a Forever build broke its old row hook, so everything must be guarded.

## Decisions

1. **What the tag shows:** the recipe's best result as the main window's banner and the pinned list value (`Controller.evaluate(recipe, 1)`, the same figure; `result.best`/net as `Present` uses for pins: reuse the pinned list's row value, do not recompute differently). Colour like pins: green gain, red loss, grey at break even or when the figure is incomplete (use the existing "incomplete" marking: amber, as for cost per point).
2. **Which recipes:** only those the addon knows with their reagents: `db.known` of the open profession (`DB`, `CraftProfitCharDB`, scanned by `Controller.refreshKnown`), found by `recipeID`. Not learned, not scanned, or without any price: **no tag** (nothing drawn). Headers/category rows: nothing.
3. **Placement:** right end of the row, left of Blizzard's own right-side widgets if any (read their position, never move them). Fixed tag width (about 60 px, right-justified, no word wrap). Because Blizzard's label may be wider than the room, a long recipe name can run under the tag: test the real appearance in game; offer the fallback in the report (tag only when `row:GetWidth()` leaves room).
4. **Cost:** one `Controller.inPass` pass per refresh of the visible rows (the ScrollBox only has ~25 live rows); never evaluate on every scroll step more than the rows that were re-initialised; no evaluation while the profession window is hidden.
5. **Refresh:** rows repaint when a row is initialised (scroll, filter, tab switch) and when prices or settings change (`Controller.refresh`/`requestRefresh` path: add the row refresh where the pinned list refresh is called, coalesced the same way; do not add a new event frame).
6. **Option:** new setting `showRowTags` (default true) in `DB` settings (sanitised, default for old saves = true), a check box in the options window (look at how another check box is added there; label e.g. "Profit on each recipe of the profession window" / FR / ES), `Controller.setShowRowTags(v)`, repaint or hide immediately.
7. **Tooltip:** none in this step.
