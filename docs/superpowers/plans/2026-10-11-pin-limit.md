# Pinned recipes limit option Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The number of recipes a character may pin becomes a setting, 12 / 20 / 30 / 40 (default 20), chosen in the options window with a plain note that a higher limit makes "Search prices" longer.

**Architecture:** `CraftProfitDB.settings.maxPins` (account wide, sanitised in `DB.lua`); `DB.MAX_PINS` (12) is replaced by `DB.PIN_LIMITS = { 12, 20, 30, 40 }`, `DB.PIN_LIMIT_DEFAULT = 20` and `DB.PINS_ABSOLUTE_MAX = 40`. `DB.initChar` never drops saved pins below the absolute maximum (a lower limit only blocks adding, it never deletes data). `DB.pinAdd(db, recipe, limit)` refuses when `#pins >= limit`. `Controller.setPinLimit(n)` validates, saves and refreshes. The options window gets a "Pinned recipes" panel with four segmented buttons (like the appearance rows: the chosen one stays lit, never a dropdown) and a two-line note.

**Tech Stack:** Lua 5.1 (WoW Forever beta, Interface 16001), `sh tests/check.sh`, fake env `tests/fakewow.lua` (never edit).

## Global Constraints

- All constraints of the earlier native plans apply (`docs/superpowers/plans/2026-10-10-native-ui-foundations.md`, `...-options-window.md`, `...-pinned-window.md`): no image/font files, game fonts and `Colors`, taint rules, guards with `type(x)`, no dropdown/Menu API, strings through `ns.L` in `Locales/enUS.lua`, `frFR.lua`, `esES.lua` with parity (never touch `esMX.lua`).
- Never delete a saved pin because of the limit: lowering the limit below the current count keeps every pin, blocks new ones, and the message says so.
- Hostile saved values (nil, strings, NaN, negative, 7, 1e9) fall back to the default 20; a valid number not in the list falls back to the nearest listed value not below it, capped at 40 (decide and test).
- The "pinned list under the main window" and the pinned recipes window must cope with up to 40 pins: scroll bars already exist; test 40 pins in both (offset clamp, wheel, "x" at the bottom).
- Message when full: "Pinned recipes limit reached (%d). Raise it in /cp options." (FR/ES translated); `L.PINS_FULL` is replaced by a keyed format with the number.
- Options window: window height recomputed from its panels; every label and the note fit in en/fr/es (use `Layout.textWidth` and the existing width checks); the note text: "A higher limit makes Search prices take longer: the auction house is searched one item at a time." (FR/ES translated; two lines at most).
